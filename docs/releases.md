# Releases

Operator procedure for cutting, publishing and rolling back a hermes-rs
release. This document describes the release surface; it does not authorize a
release.

## Status today

- **No release exists.** `git tag` is empty, `git ls-remote --tags origin` is
  empty, and there is no GitHub Release or published artifact. The repository
  installs from a source checkout only.
- `Cargo.toml` carries `[package] version = "0.1.0"`. That is the crate's
  initial manifest version, not a release decision.
- The release surface described here was added by `RELEASE-001`. Adding it
  created no tag, no commit-tagged artifact and no publication.
- Nothing in this document is a permission. The cut requires a readiness sweep
  that returned **GO** (see [Standing gate set](#standing-gate-set)).

## No-claim rule

hermes-rs is an independent Rust project. It is **not** an official Nous
Research release, it is not affiliated with or endorsed by Nous Research, and it
is **not a drop-in replacement** for Hermes Agent. Neither the driver, the
workflow, the changelog nor a release's text may state a compatibility, parity
or performance claim that is not backed by a repeatable artifact committed under
`docs/evidence/`. The release body generated by CI opens with that disclaimer
for the same reason.

## Surfaces

| Path | Role |
|---|---|
| `scripts/release.sh` | The release driver: preconditions, gates, artifact build, `SHA256SUMS`, CHANGELOG stamp, local commit and local tag. Never pushes. |
| `CHANGELOG.md` | Keep-a-Changelog file. `## [Unreleased]` at the top; the driver writes `## [<version>] - <YYYY-MM-DD>` at cut time. |
| `.github/workflows/release.yml` | Publishes: runs **only** on `push` of a `v*` tag or on `workflow_dispatch` with an existing tag. Cross-compiles both binaries for `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu`, writes `SHA256SUMS`, verifies it, and creates the GitHub Release. |
| `docs/evidence/release-001/` | The real, captured evidence for the driver: a dry run and the refusal paths. |

The workflow does not run on ordinary pushes to `main` — the only `push`
trigger is `tags: ['v*']`.

## Before cutting

All of the following must be true. Anything missing is a NO-GO, not a caveat.

1. `main` is at `origin/main`, the working tree is clean, and the commit you
   intend to release is the one you inspected.
2. The hosted CI gate is green **at that exact commit**: the `CI` workflow
   (project contracts + board integrity). The `Rust CI` workflow is
   path-filtered on Rust inputs; if the release commit is board/docs-only, prove
   tree identity instead of assuming a missing run means green
   (`git diff --name-only <last-rust-ci-sha>..HEAD` must touch no `.rs`,
   `Cargo.toml` or `Cargo.lock`).
3. The local gate replay passes on that commit:
   ```sh
   cargo fmt --all -- --check
   cargo clippy --workspace --all-targets --all-features -- -D warnings
   cargo test --workspace --all-features
   python3 scripts/check-project-artifacts.py
   python3 scripts/check_skill_claims.py
   ```
4. `cargo audit --json` reports zero vulnerabilities. A disclosed, accepted
   advisory warning (currently `RUSTSEC-2026-0253` under `SEC-HRS-001`) is not a
   blocker but must stay visible in the release record.
5. The readiness sweep row returned **GO** for this version and commit. The
   driver makes you name that row; it cannot verify the decision for you.

## Cut procedure

```sh
# 1. Inspect the plan. Writes no tag, no commit and no repository file.
scripts/release.sh --dry-run ; echo "rc=$?"

# 2. Confirm the version stamp. Bumping it is a deliberate, separate commit;
#    the driver never invents a version.
grep -n '^version' Cargo.toml            # [package] version -> tag v<version>

# 3. Cut. Refuses unless the tree is clean, HEAD is on main, the tag is absent
#    locally and on origin, [Unreleased] is non-empty, and --confirm-readiness
#    names the GO row.
scripts/release.sh --confirm-readiness <readiness-row-id>

# 4. Review what the cut produced, then push (the driver never pushes).
git show --stat HEAD
git tag -n9 --list 'v*'
git push origin main
git push origin v<version>
```

The cut performs, in order: precondition refusals → `cargo fmt`/`clippy`/`test`
→ `cargo build --release --locked` for the host target → artifacts,
`RELEASE-NOTES-<tag>.md` and `SHA256SUMS` under
`target/release-artifacts/<tag>/` (gitignored) → the dated `CHANGELOG.md`
section (with an empty `## [Unreleased]` left at the top) → a commit
`release: v<version>` touching only `CHANGELOG.md` → an annotated local tag.

The driver **refuses** (exit 2, explicit message) on: dirty tree, HEAD not on
`main`, tag present locally, tag present on `origin`, origin tag check not
completable (fail closed), a version that already has a dated CHANGELOG
section, an empty `[Unreleased]`, or a missing `--confirm-readiness`. It
**fails** (exit 1) on version-stamp drift between `Cargo.toml` and `Cargo.lock`,
a malformed changelog, a failing gate, or a failing artifact build.

Safety on a clean tree with the current `0.1.0` stamp: a bare
`scripts/release.sh` **refuses** with an explicit message — it does not no-op
silently. Use `--dry-run` to inspect the plan for free.

## Publish procedure

Pushing the tag is what publishes. `release.yml` then:

1. resolves the tag from the push ref (or the `workflow_dispatch` input),
2. fails unless the tag is a `main`-line commit and matches
   `Cargo.toml`'s `[package] version`,
3. fails unless `CHANGELOG.md` has a dated section for that version (a tag
   without a changelog entry publishes nothing),
4. builds both binaries for both targets on the stable channel selected by
   `rust-toolchain.toml` (`gcc-aarch64-linux-gnu` for the aarch64 leg),
5. smoke-runs the host-target binaries (`--version` must print
   `hermes-rs <version>`, `--protocol` must print
   `hermes-rs/session-adapter/1`),
6. generates `SHA256SUMS`, verifies it with `sha256sum -c`, and
7. creates the GitHub Release with all four binaries plus `SHA256SUMS`.

Replaying a publish without re-cutting: `workflow_dispatch` with the existing
tag as the `tag` input — same checks, same output.

### Artifact names

```
hermes-rs-v<version>-x86_64-unknown-linux-gnu
hermes-rs-v<version>-aarch64-unknown-linux-gnu
hermes-rs-session-adapter-v<version>-x86_64-unknown-linux-gnu
hermes-rs-session-adapter-v<version>-aarch64-unknown-linux-gnu
SHA256SUMS
```

For `0.1.0` that is `hermes-rs-v0.1.0-x86_64-unknown-linux-gnu` and so on.
SQLite is statically linked through `rusqlite`'s `bundled` feature; libc is the
target's glibc. No fully-static (musl) artifact is produced and none is claimed.

### Verify a published release

```sh
gh release download v<version> --pattern '*' --dir /tmp/hermes-rs-release
cd /tmp/hermes-rs-release
sha256sum -c SHA256SUMS
chmod +x hermes-rs-v<version>-x86_64-unknown-linux-gnu \
          hermes-rs-session-adapter-v<version>-x86_64-unknown-linux-gnu
./hermes-rs-v<version>-x86_64-unknown-linux-gnu --version     # hermes-rs <version>
./hermes-rs-session-adapter-v<version>-x86_64-unknown-linux-gnu --protocol
```

The aarch64 binaries cannot be executed on the x86_64 runner; they are
cross-compiled and their architecture is recorded in the workflow log. Do not
claim an aarch64 run that was never performed.

## Rollback

Rollback is a deliberate, published act — not a revert of a private branch. In
order:

1. **Stop the release from being consumed.** Delete the GitHub Release (the
   tag stays):
   ```sh
   gh release delete v<version> --yes
   ```
2. **Withdraw the tag.** A published artifact must not keep a tag that no
   longer corresponds to the shipped commit. Delete it on the remote and
   locally:
   ```sh
   git push origin :refs/tags/v<version>
   git tag -d v<version>
   ```
3. **Revert the release commit** so the changelog returns to `[Unreleased]`:
   ```sh
   git revert --no-edit <release-commit-sha>
   git push origin main
   ```
   The revert restores the entries under `## [Unreleased]`; nothing is deleted
   from history.
4. **Record why.** A rollback without a recorded cause is indistinguishable from
   a bad cut. Note the failing evidence in the board row that ordered the cut.

Re-pointing a tag at a different commit instead of deleting it is possible
(`git tag -f` + `git push --force origin v<version>`) but it invalidates every
`SHA256SUMS` copy already downloaded and makes verification ambiguous. Prefer
delete-and-recut, or cut the next patch version.

## Standing gate set

A cut requires every one of these; none is satisfied by this document or by the
driver's existence:

| Gate | What it means |
|---|---|
| Readiness sweep returns GO | The scheduler-owned readiness row for this version and commit. The driver only records the row you name. |
| Paired upstream-harness comparative run (AC-2/AC-9) | Not yet executed; the compatibility matrix row "Upstream test framework and comparative scoring" is still `Untriaged`, so no parity claim may accompany a release. |
| Install, upgrade and release behavior (AC-6) | The matrix row is `Untriaged`; no install/upgrade/rollback implementation exists yet, so a release cannot carry an upgrade-safety claim. |
| Clean-machine install proof | The fresh-machine install leg is blocked (`DF-HRS-123`); until it runs, "installs from source on a clean host" is unproven. |
| QA battery on a fresh system | The bunker battery row is pending on host capacity, not passed. |
| Security review | `cargo audit` clean apart from the disclosed `RUSTSEC-2026-0253` warning under `SEC-HRS-001`; branch protection on `main` remains an open owner decision. |

## What this surface deliberately does not do

- It does not bump versions, invent changelog text, or create a release
  candidate.
- It does not push, upload, or publish anything; publication is a separate
  operator step plus CI.
- It does not make a release authorized. Only a readiness GO does that.
